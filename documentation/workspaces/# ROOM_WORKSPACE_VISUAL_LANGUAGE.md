\# ROOM\_WORKSPACE\_VISUAL\_LANGUAGE.md



Status: Visual Language Definition v1

Module: Room Workspace

Repository: Vanara Central

Owner: Product Design



\---



\# 1. Purpose



This document defines the visual language of Room Workspace.



Not the business logic.



Not the implementation.



This document defines how Vanara should feel.



Every future workspace should gradually inherit these same principles.



Room Workspace becomes the reference implementation of the Vanara Design System.



\---



\# 2. Emotional Goal



The application should feel:



Calm.



Premium.



Confident.



Operational.



Never stressful.



Never noisy.



Never enterprise.



The interface should resemble a luxury boutique hotel.



Not hotel software.



\---



\# 3. First Impression



When opening a room the user should immediately recognise:



"This is MY room."



Not:



"This is another database record."



Recognition is more important than information.



Information comes immediately after recognition.



\---



\# 4. Hero Philosophy



Every room begins with its photograph.



The photograph is not decoration.



The photograph creates identity.



The user should recognise the room before reading its number.



The hero therefore becomes part of navigation.



\---



\# 5. Visual Hierarchy



Hierarchy never changes.



Level 1



Room Identity



↓



Level 2



Operational Situation



↓



Level 3



Guest



↓



Level 4



Current Work



↓



Level 5



History



The eye always follows this order.



\---



\# 6. Density



Vanara is information dense.



Not visually dense.



Large empty spaces are avoided.



Large decorative panels are avoided.



Every centimetre of scrolling should provide operational value.



\---



\# 7. Cards



Cards are not containers.



Cards are operational objects.



Every card answers exactly one question.



Examples:



Guest



Who is here?



Maintenance



Is there a technical problem?



Housekeeping



Do I have work?



Reception



Is check-in complete?



If a card answers two questions it should probably become two cards.



\---



\# 8. Corners



Every card shares one radius.



Never mix:



8px



12px



24px



throughout the same page.



Consistency is more important than fashion.



\---



\# 9. Shadows



Shadows are minimal.



Cards separate through spacing.



Not heavy elevation.



Vanara prefers layers over shadows.



\---



\# 10. Borders



Borders are extremely subtle.



Cards should appear separated naturally.



Not boxed.



\---



\# 11. Colour



Colour communicates state.



Never decoration.



Green



↓



Everything OK



Amber



↓



Attention



Red



↓



Blocking



Blue



↓



Information



Grey



↓



Secondary



Colour never replaces text.



\---



\# 12. Typography



Typography must never shout.



Hierarchy comes from:



weight



spacing



position



not giant font sizes.



Room Name is always the largest text.



Everything else follows.



\---



\# 13. Guest



Guest identity is important.



Nationality is secondary.



OTA is tertiary.



Booking ID never appears.



Database IDs never appear.



\---



\# 14. Status Pills



Status pills are extremely compact.



Examples:



CLEAN



DIRTY



OCCUPIED



OPERATING



BLOCKED



Never oversized.



Never decorative.



Never colourful badges occupying the whole width.



\---



\# 15. Icons



Icons support reading.



They never replace reading.



The application must remain usable without interpreting icons.



\---



\# 16. Photography



One official room photograph.



Always.



The same image is reused across the application.



The room acquires visual identity.



\---



\# 17. Motion



Motion is slow enough to understand.



Fast enough not to delay work.



Motion exists only to preserve context.



Never to entertain.



\---



\# 18. Reading Direction



The interface is read vertically.



Never force the user to zig-zag horizontally.



Cards naturally create one reading column.



\---



\# 19. Empty Space



Empty space is intentional.



It separates concepts.



It never exists because the layout is unfinished.



\---



\# 20. Progressive Disclosure



Never display information before it becomes useful.



Every interaction reveals exactly one new level of detail.



Nothing appears suddenly.



Nothing disappears suddenly.



\---



\# 21. Calm Interface



The interface must never create anxiety.



Examples of forbidden behaviour:



multiple blinking indicators



competing colours



animated badges



flashing alerts



moving backgrounds



Every alert should feel controlled.



\---



\# 22. Operational First



Every visual decision answers one question:



"Does this help someone work faster?"



If not,



remove it.



\---



\# 23. Premium Rule



Luxury in Vanara does NOT come from:



gold



gradients



glassmorphism



heavy shadows



It comes from:



consistency



spacing



typography



photography



motion



restraint



\---



\# 24. Permanent Design Rule



If two visual solutions communicate the same information,



always choose the quieter one.



Calm interfaces reduce cognitive load.



Reducing cognitive load is the primary visual objective of Vanara Central.
