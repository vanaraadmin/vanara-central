\# VANARA\_DESIGN\_SYSTEM\_FOUNDATIONS.md



Status: Foundation v1



Repository: Vanara Central



Owner: Product Design



Scope:



Entire application



\---



\# 1. Purpose



This document defines the permanent Design Language of Vanara Central.



It is independent from any single workspace.



Every future module must inherit these rules.



No workspace may redefine them.



The objective is visual consistency.



The user should always feel they are using one application.



Never multiple applications stitched together.



\---



\# 2. Design Philosophy



Vanara is built around one concept:



Operational Calm.



The interface should reduce cognitive load.



Not increase it.



Every visual decision should help staff make faster decisions.



Never impress.



Always help.



\---



\# 3. Product Personality



Vanara is:



Calm



Premium



Elegant



Operational



Human



Minimal



Never:



Enterprise



Corporate



Aggressive



Gamified



Decorative

\---



\# 5. Progressive Disclosure



Nothing appears before it becomes useful.



Information unfolds.



Never overwhelms.



The application always answers:



"What do I need now?"



before



"What else exists?"



\---



\# 6. Navigation Philosophy



Navigation is expensive.



Disclosure is cheap.



Always prefer:



Tap



↓



Reveal



instead of



Tap



↓



New Page



Only navigate when absolutely necessary.



\---



\# 7. Dismiss Philosophy



Global Rule.



Every temporary interface closes naturally.



Allowed:



Outside click



ESC



Tap another item



Swipe down (future)



Forbidden:



Dedicated Close buttons



unless destructive workflows require confirmation.



\---



\# 8. Motion Philosophy



Motion communicates.



Motion never decorates.



Animation exists only to preserve context.



Never to entertain.



If animation does not improve understanding,



remove it.



\---



\# 9. Information Hierarchy



Every screen follows:



Identity



↓



Situation



↓



Current Work



↓



Actions



↓



History



Never reverse this order.



\---



\# 10. Cards



Cards are operational objects.



Not containers.



Every card answers one question.



If a card answers multiple unrelated questions,



split it.



\---



\# 11. One Question Rule



Examples



Guest Card



↓



Who is staying?



Maintenance



↓



Is there a problem?



Housekeeping



↓



Do I have work?



Reception



↓



Is check-in complete?



Every card has one purpose.



\---



\# 12. Colour



Colour is state.



Never decoration.



Green



↓



Healthy



Amber



↓



Attention



Red



↓



Blocking



Blue



↓



Information



Grey



↓



Secondary



Colour never replaces text.



\---



\# 13. Typography



Hierarchy comes from:



weight



spacing



position



Not giant font sizes.



Readability always wins.



If Product Owner says:



"It is difficult to read."



Increase the size.



No discussion.



\---



\# 14. Photography



Every accommodation owns one official image.



Recognition is operational.



The same image is reused everywhere.



Never duplicate image systems.



\---



\# 15. Compact First



Every new workspace starts compact.



Only then expands.



Large dashboards are discouraged.



Large cards are discouraged.



The application should display as much operational information as possible without becoming noisy.



\---



\# 16. Empty Space



Whitespace separates concepts.



Not content.



Never create decorative whitespace.



Every scroll should reveal operational value.



\---



\# 17. Component Reuse



No workspace invents its own:



Buttons



Cards



Hero



Status Pills



Empty States



Progress Indicators



Every reusable component becomes part of the Design System.



\---



\# 18. Icons



Icons reinforce.



Text explains.



Never rely on icon interpretation alone.



\---



\# 19. Alerts



Alerts are calm.



Never flashing.



Never blinking.



Never animated.



Blocking



↓



Red



Attention



↓



Amber



Information



↓



Blue



Done.



\---



\# 20. Motion Timing



Expand



180–220 ms



Collapse



180–220 ms



Status Change



150–180 ms



Button Feedback



100–150 ms



No animation exceeds 250 ms.



The interface should feel immediate.



\---



\# 21. Global Interaction Rules



Tap outside



↓



Dismiss



One expanded object at a time



No Close buttons



Progressive disclosure



Contextual actions



Sticky actions only where operationally required



Optimistic updates whenever safe



These rules are mandatory.



\---



\# 22. Readability Rule



Operational users always win over visual minimalism.



A beautiful interface nobody can read is considered a failed interface.



Readability is the primary KPI.



\---



\# 23. Performance Rule



Performance is perceived.



Smooth interaction is more important than visual effects.



Prefer:



Simple transitions



Fast rendering



Stable layout



over



Complex animations



\---



\# 24. Future Modules



Every future workspace must inherit this document.



Examples



Reception



Housekeeping



Maintenance



Rooms



Procurement



Dashboard



Chat



Future AI



No module may create its own visual language.



\---



\# 25. Permanent Rule



Vanara Central must always feel like one product designed by one person.



Not a collection of independently developed modules.



Consistency is considered a functional requirement.



Not an aesthetic preference.
